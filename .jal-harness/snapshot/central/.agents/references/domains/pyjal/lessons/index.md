# 재사용 교훈

- [배치 완료는 모집단과 보존 축으로 판정한다](batch-verdicts.md) - 처리 건수 하나 대신 입력 모집단·변경 대상·보존 대상·영속 결과를 함께 대조한다.
- [호환성은 소비처의 계약으로 판단한다](contracts.md) - 변경량 대신 입력·출력·저장 형식·실패 의미와 실제 소비처를 기준으로 범위를 정한다.
- [결정 질문에는 실제 선택과 근거를 담는다](decision-questions.md) - 진행 승인과 정책 선택을 구분하고 필요한 결정에 측정한 대안을 제시한다.
- [배포는 파일과 최종 변경 이력으로 확인한다](deployment-evidence.md) - 개발 테스트 통과와 실제 배포본 반영을 별도의 증거로 확인한다.
- [테스트가 결함을 볼 수 있는지 먼저 확인한다](discriminating-tests.md) - 통과 여부보다 해당 결함이 실제 검증 대상과 관측 지점에 도달하는지 먼저 확인한다.
- [측정 증거와 프로브의 수명을 명시한다](evidence-lifetime.md) - 나중에 결정을 설명할 증거는 생성 직후 보존하고 정리 대상과 구분한다.
- [실행된 소스와 경로를 증거로 남긴다](execution-origin.md) - 검증할 코드가 실제로 로드됐는지와 어떤 실행 경로를 탔는지를 확인한다.
- [반복된 교훈을 실행 지점에 연결한다](gates.md) - 문서에 적힌 교훈이 재발하면 필요한 작업 단계와 확인 가능한 가드에 연결한다.
- [성능은 사용자가 쓰는 조건에서 잰다](measurement-context.md) - 호스트·자산·모드·조건 조합을 맞춰 성능의 목표와 지배 비용을 측정한다.
- [관측과 원인 해석을 분리한다](premises.md) - 요청·계획·기존 문서의 사실 주장도 실제 입력과 코드에서 다시 확인한다.
- [호출 반환값과 실제 결과를 구분한다](readback.md) - 성공 반환·예외 없음·종료 코드만으로 저장과 변경의 완료를 판정하지 않는다.
- [UI 구조 검증과 실제 사용 판정을 구분한다](ui-reality.md) - 구조·시그널 테스트와 실제 클릭·크기·스크롤·스타일의 사용자 경험을 각각 검증한다.
