# Codex 어댑터

Codex 앱의 관리 worktree와 Codex CLI는 구분한다. 이번 작업의 Codex 앱 환경에서는 관리 worktree 생성 후 지시서 작성, 별도 테스터 실행·테스트 커밋·종료 반환, 같은 worktree의 별도 구현자 배정이 관찰되었다. CLI 단독의 동일한 작업공간 가시성·사용자 개입, 실패·재개 전체 수명주기는 미실증이다. 현재 세션에 공개된 도구 스키마와 설치 버전 공식 문서로 기능을 확인한다.

관리 worktree 도구가 있으면 코디네이터가 그것을 사용하며 같은 자원을 다른 관리자로 중복 관리하지 않는다. CLI 단독에 해당 기능이 없으면 코디네이터가 `git worktree add <절대경로> -b <브랜치> <base-ref>`로 준비한다. 명령 전 실제 도움말·기준 저장소·기존 자원을 확인한다. setup·exclude·지시서·공용 안내가 준비된 뒤에만 에이전트를 실행한다.

현재 제공된 collaboration spawn_agent는 task_name·message 등을 받아 별도 에이전트를 실행하며 전용 cwd 인자가 없는 환경에서는 메시지에 절대 경로·브랜치·지시서를 명시하고 워커가 첫 편집 전에 실제 위치를 확인한다. 부모와 같은 cwd를 공유할 수 있으므로 명령마다 작업 경로를 지정한다. 지원되지 않는 cwd 플래그나 권한 우회를 만들어 쓰지 않는다. 테스터의 결과와 공식 완료 상태를 확인한 다음 별도 구현자를 생성한다. 이 흐름이 항상 호스트 사이드바의 독립 워크스페이스로 표시된다고 주장하지 않는다.

send_message·결과 반환·상태 조회가 제공되면 자율형 질문·완료 추적에 사용한다. 직접 질문 채널이 없으면 질문·변경·재개 정보를 반환하고 종료한 뒤 코디네이터가 답변을 넣어 재실행한다. 상태가 불명확한 에이전트는 다시 띄우지 않는다. 개입형 직접 대화가 지원되지 않으면 사용자가 작업 폴더에서 `codex` 별도 세션을 열고 지시서를 가리키도록 요청한다. 서브 에이전트 스레드 표시를 사용자 직접 개입과 동일시하지 않는다.

코디네이터는 작업 경로를 지정한 셸로 테스트와 보호 변경을 검사한다. 사용자 설정과 sandbox·approval 정책을 상속·준수하며 권한을 임의 확대하지 않는다. 별도 세션은 공식 완료 정보 또는 사용자 확인·결과 전달을 확보해야 후속 역할을 실행한다. 문서·fixture 검증과 실제 에이전트 준수 실험은 별도 보고한다.
