# 워커 지시서와 실행 계약

## 위치·생성·제외

코디네이터만 작업 worktree 루트의 `.jal-harness-task.md`를 생성·갱신한다. 작업 생성·환경 준비 성공 후, 워커 시작 전에 작성한다. 먼저 `git ls-files -- .jal-harness-task.md`와 파일 존재를 확인한다. 이미 추적되거나 같은 이름의 현지 파일이 있으면 덮어쓰지 않고 조율한다. `git rev-parse --path-format=absolute --git-common-dir`로 찾은 기존 공통 Git 디렉터리의 `info/exclude` 내용을 보존하며 `/.jal-harness-task.md` 한 줄을 추가한다. 파일이 없으면 부모 디렉터리를 안전하게 확인해 생성한다. `git check-ignore .jal-harness-task.md`로 확인한다. 일반적인 add·commit에서 제외될 뿐 `git add -f`까지 막는다고 주장하지 않는다.

지시서는 Git 이력·관리 자산·resolver/snapshot·배포에 넣지 않으며 실행 상태 장부로 사용하지 않는다. 공용 안내는 기준 checkout의 ACTIVE_WORK.md 정본 하나만 코디네이터가 유지한다. 지시서와 안내는 서로 사본이 아니다. 중단 시 변경·자원·재개에 필요한 지시서와 책임을 보존한다. 정상 종료 시 승인된 통합·재검증·정리 절차로 작업 자원과 함께 처리한다.

## 세 섹션 형식 (형식 버전 1)

다음은 설명용 예시이며 실제 지시서 자산을 설치하지 않는다. 경로는 실제 저장소 절대 경로로 작성한다.

```markdown
# 작업 공통
- 형식 버전: 1
- 작업 ID: <고유 ID>
- 모드: <자율형 / 개입형>
- 작업 경로·브랜치: <절대 경로>, <실제 브랜치>
- 편집 소유권: <제품·보호 테스트 등 역할별 경계>
- 읽을 지침 본문: <중앙·프로젝트 본문의 절대 경로 목록>
- 출처: <중앙 커밋·버전·source·stale>
- 작업 고유 제약: <중앙에 없는 공개 시그니처 유지·수정 금지 등>
- 선행 결과·base ref·반영 시점: <커밋·계약·검증·주의 사항>
- 완료 기준: <검사 가능한 결과>
- 실행 환경: <필요한 setup 결과·공유 자원 배정·실행 위치>

# 인수 기준
- 인수 조건: <테스트 커밋의 조건 요약>
- 보호 경로: <저장소 루트 기준 명시적 파일·디렉터리 목록>
- 구현자 허용 단위 테스트 경로: <명시적 목록 또는 없음>
- 테스트 기준 커밋: <전체 Git 커밋>
- 실행 명령: <작업 경로에서 실행할 명령·조건>

# 역할별
- 현재 역할: <테스터 / 구현자 / 중앙 지식 담당>
- 역할별 지시: <이번 실행의 범위·완료 기준>
- 질문 경로: <자율형 코디네이터 / 개입형 사용자, 실제 채널>
- 추가 지침: <이번 역할에 필요한 추가 지시>
```

작업 공통은 작업 생성 시 확정하고 이후 불변이다. 인수 기준은 테스터 완료 전에는 미확정임을 표시하고, 테스터의 테스트 커밋과 종료 확인 후 코디네이터가 확정한다. 정본은 테스트 커밋이며 섹션은 그 커밋을 가리키는 요약이다. 역할별은 역할 교체 시 갱신한다. 코디네이터는 테스터 종료 확인 후 인수 기준을 확정하고 역할별을 구현자용으로 바꾼 뒤 서로 다른 구현자 에이전트를 실행한다. 한 에이전트를 양 역할로 바꾸지 않는다.

중앙 지식 검토·정제·통합을 한 에이전트에 배정할 때는 역할을 `중앙 지식 담당`으로 적는다. 인수 기준 섹션 대신 `knowledge-check <central> --base <기본 브랜치> [--candidate <ID>]` 실패 없음과 `CHECK_SHA256` 기록을 완료 기준으로 적으며 테스터·구현자 분리와 아래 보호 테스트 감사는 적용하지 않는다. 이 검사 결과는 자료·문서 무결성이며 지식 주장의 사실 검증이 아니다. 제품 코드·테스트·실행 도구 변경이 섞이면 그 부분만 별도 테스터·구현자 작업으로 분리한다.

확정된 작업 공통·인수 기준은 일반 갱신 대상이 아니다. 인수 변경은 코디네이터가 별도 테스터를 실행해 요구사항·근거에 따라 테스트를 수정·커밋하도록 한 뒤 기준 커밋과 인수 섹션을 다시 확정한다. 작업 공통의 범위 변경이 필요하면 기존 배정을 중단하고 사용자와 변경된 작업을 조율한 뒤 새 작업 계약을 확정한다. 개입형 사용자 요청도 이 경로를 따른다. 지시서를 몰래 고쳐 승인·보호 범위를 넓히지 않는다.

## 읽기와 역할 확인

프로젝트 AGENTS.md의 네 가지 시작 분기를 재개에도 적용한다. 워커는 지시서 형식 버전·작업 ID·역할·절대 경로·실제 브랜치·질문 경로와 배정 일치를 확인하고 지시서에 열거된 본문을 전부 읽는다. 배정 불일치·누락은 편집을 보류하고 배정자에게 질문한다. 배정 없이 지시서만 있으면 그 역할의 워커이며 새 코디네이터나 추가 worktree를 만들지 않는다.

코디네이터가 resolver로 중앙 연결과 자료를 확인하고 범위에 필요한 본문 절대 경로를 선별한다. 중앙 요약본은 지시서에 옮기지 않고 중앙에 없는 작업 고유 제약만 직접 적는다. 연결 worktree에는 중앙 본문 경로를, 중앙에 접근할 수 없는 단독 클론에는 마지막 검증 사본의 실제 경로와 source=snapshot·stale=true를 기록한다. 출처 커밋·버전·source·stale은 기록이며 워커의 재검증 의무가 아니다. 읽는 동안 중앙 본문이 바뀌어 더 새 버전을 읽는 것은 허용하며 기록된 커밋으로 차이를 추적한다. 별도 중앙 고정 사본이나 워커 해시 검증을 추가하지 않는다.

워커의 목록 본문 읽기는 탐색이 아니다. 워커는 resolver·중앙 색인·목록 밖 중앙 본문을 탐색하지 않는다. 필요한 본문이 없거나 접근할 수 없으면 질문 경로로 요청하고 그 판단·작업을 보류한다. 지시서 외의 중앙 문서를 임의로 찾아 규칙을 바꾸지 않는다.

## 보호 테스트 감사와 최종 판정

테스터는 인수·회귀 테스트, 관련 fixture·기대 결과·실행 설정의 보호 목록을 저장소 루트 기준으로 명시한다. 구현자 허용 내부 단위 테스트 경로와 겹치면 실행 전에 조율한다. 코디네이터는 기준 커밋의 유효성과 다음 근거를 함께 확인한다.

1. `git diff --name-status --no-renames <기준커밋> HEAD --`로 커밋 변경을 확인한다.
2. `git diff --name-status --no-renames HEAD --`와 `git diff --cached --name-status --no-renames --`로 미커밋·staged 변경을 확인한다. `git diff --no-renames <기준커밋> --`로 실제 작업 내용도 비교한다.
3. `git ls-files --others --exclude-standard`로 미추적 변경을 확인한다. 필요하면 실행에 영향을 주는 ignored 현지 설정도 점검한다. 삭제·이름 변경은 이전·새 경로 모두 보호 목록과 대조한다.
4. 파일 목록만으로 끝내지 않고 테스트 본문·실행 설정·CI·명령의 diff와 실제 실행 결과를 검토한다. skip·선택 필터·fixture 변경·런너 대체 등 실행 제외·우회가 없는지 확인한다. 허용 내부 단위 테스트와 보호 테스트를 구분한다.
5. 보호 변경이 있으면 구현자가 정당화하거나 임의 수정하지 않고 별도 테스터 경로로 돌린다. 문서에 의한 사후 확인이지 파일 쓰기를 기계적으로 차단하는 보안 장치는 아니다.

코디네이터가 실제 코드 커밋·dirty 상태·환경·데이터 조건·명령·결과·증거·미검증 항목을 기록해 최종 판정하고 통합 후 실제 통합 커밋에서도 재검증한다. 필수 user_pending·insufficient_evidence는 완료가 아니다. 개입형 사용자 완료 판정과 기술 검증 모두 필요하다.

## 질문·결과·중단·재개

누락·모호함·범위 밖 문제는 자율형에서 코디네이터, 개입형에서 해당 워크스페이스 사용자에게 직접 질문하고 해당 작업을 보류한다. 직접 채널이 없으면 질문·현재 변경·재개 정보를 결과로 반환하고 종료한다. 코디네이터는 답변을 포함해 새 실행을 시작한다. 개입형 직접 질문 기능이 없으면 그 한계를 알리고 별도 사용자 세션을 사용한다.

결과는 완료·질문 대기·실패·중단을 구분하고 작업 ID, 코드 버전, 변경, 검증, 근거, 남은 문제와 재개 정보를 포함한다. 호스트 완료 신호와 세션 식별자로 실제 종료를 확인하며 화면의 조용함만으로 종료를 추정하지 않는다. 상태 불명 워커를 중복 실행하지 않는다. 직접 종료 확인을 제공하지 않는 호스트는 사용자 확인 또는 공식 완료 이벤트를 확보하기 전 후속 편집자를 실행하지 않는다. 이 결과 계약을 별도 실행 상태 장부로 복제하지 않는다.
